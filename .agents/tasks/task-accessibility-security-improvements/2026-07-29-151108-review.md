# Security headers, error pages, and accessibility polish for Kiro Hub (v2)

This change adds six security headers via Next.js config, a custom 404 page, a client-side error boundary, CSS and Framer Motion reduced-motion support, and a metadata title template with matching short titles across all child pages. All four issues from the v1 review have been addressed: `interest-cohort` replaced with `browsing-topics`, `MotionConfig reducedMotion="user"` added to the provider tree, child pages migrated to short titles, and a TODO comment added for future error reporting.

**Watch for:**
- HSTS preload with `includeSubDomains` assumes all subdomains of `kirohub.dev` are TLS-only (likely) — if any subdomain lacks TLS, HSTS preload submission will brick it for up to 2 years.
- `unstable_retry` API is prefixed as unstable in Next.js 16 (confirmed) — a future Next.js release may rename or remove it, requiring a migration in `error.tsx`.

**Verdict**: APPROVED

## High-level view

The security header set carries one deployment risk: HSTS with `includeSubDomains; preload` is a near-irreversible commitment once submitted to the preload list. For a site with no known subdomains this is acceptable, but worth confirming before actual preload list submission.

Reduced-motion coverage is now two-layered: the CSS media query handles stylesheet animations and the `MotionConfig` wrapper handles Framer Motion's JS-driven animations. The v1 gap where Framer Motion ignored the user preference is closed.

The `unstable_retry` prop in `error.tsx` is explicitly marked unstable in Next.js 16, signaling it may change in a minor release. Worth tracking but not blocking.

## HSTS preload commitment

The `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` header is the strongest HSTS posture available. The `preload` directive is informational until the domain is actually submitted to hstspreload.org, so merely shipping this header is safe. The risk materializes only at submission time: once accepted, browsers hardcode HTTPS for the domain and all subdomains for the max-age period. If a staging subdomain (e.g., `staging.kirohub.dev`) or an internal tool exists on plain HTTP, it becomes unreachable. The failure mode is silent and long-lived — worth confirming subdomain inventory before submission.

## Unstable Next.js 16 error boundary API

The `unstable_retry` prop replaces the `reset()` function from earlier App Router versions. The `unstable_` prefix signals that the API surface may change in a minor release. The component is simple enough that migration will be trivial (likely just a rename), but it should be tracked against the Next.js changelog.
