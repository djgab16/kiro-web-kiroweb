# Security headers, error pages, and accessibility polish for Kiro Hub

This change hardens the site's HTTP response posture with six security headers, adds a custom 404 page and a client-side error boundary, introduces a global `prefers-reduced-motion` override, and converts the root metadata to use Next.js's title template pattern. The approach is straightforward: all security headers are applied via Next.js config's `headers()` function, the error pages use standard App Router conventions, and the motion override uses a CSS universal selector.

**Watch for:**
- The `interest-cohort=()` Permissions-Policy directive is deprecated and rejected by Chrome (confirmed) — it's harmless but noisy in DevTools.
- The CSS reduced-motion override kills all CSS transitions/animations globally but does not affect Framer Motion's JS-driven animations (confirmed) — users with reduced-motion preference will still see motion from 14+ components.
- The metadata title template is defined but no child page uses it yet (confirmed) — every child page still sets a full title string, resulting in doubled site names in `<title>`.

## High-level view

The security headers are a solid baseline applied to all routes. One directive (`interest-cohort`) targets an API that Chrome deprecated in favor of Topics, so it generates console warnings without providing protection. `X-XSS-Protection` is similarly legacy (modern browsers removed XSS Auditor) but defensible for older user agents.

The reduced-motion CSS media query catches transitions and animations defined in stylesheets, but Framer Motion (used across all page-level content components) animates via JavaScript and the Web Animations API. The CSS override won't suppress those animations. Framer Motion respects `prefers-reduced-motion` natively when configured, but none of the components in this codebase opt in.

The title template introduces `%s | Kiro Hub` but every child page exports `title` as a full descriptive string, so rendered titles become `"About Kiro - AI-Powered Development Assistant | Kiro Hub"` — the site name appears twice.

The error boundary uses the Next.js 16 `unstable_retry` prop but has no external error reporting. Errors caught in production are invisible unless the browser console is open.

## Security header selection and `interest-cohort` deprecation

Two headers are worth noting as legacy: `X-XSS-Protection: 1; mode=block` targets browsers with XSS Auditor (Edge pre-Chromium, old Safari), and `interest-cohort=()` in Permissions-Policy targets Google's now-abandoned FLoC API. Chrome logs a deprecation warning for `interest-cohort` because the directive was removed from the spec. It creates noise during development and signals to auditors that the header list hasn't been updated recently. If the intent is to block behavioral tracking APIs, `browsing-topics=()` is the current directive.

The HSTS max-age of 63072000 seconds (2 years) with `includeSubDomains; preload` is aggressive — appropriate for a production site committed to HTTPS, but worth confirming that `kirohub.dev` and all subdomains are indeed TLS-only before submitting to the preload list. Misconfigured HSTS preload can lock out subdomains that aren't yet on TLS.

## Reduced-motion coverage gap with Framer Motion

The CSS media query disables CSS-defined keyframe animations (`animate-fade-in`, `animate-slide-down`) and the body's color transition. But the site's primary animations come from Framer Motion (v12.42), which animates via `style` mutations and the Web Animations API. Components like `AboutContent`, `CommunityContent`, `ContactContent`, `DemoContent`, `FAQContent`, and others use `motion.h1`, `motion.p`, `motion.div` with `initial`/`animate`/`whileInView` props — all unaffected by the CSS override.

Framer Motion respects `prefers-reduced-motion` only when the application opts in via `<MotionConfig reducedMotion="user">` (wrapping the tree) or by reading `useReducedMotion()` in each component. Neither mechanism is present. The result is that a user requesting reduced motion gets CSS animations suppressed but still sees all JS-driven entrance and scroll-triggered animations — the majority of motion on the site.

## Error boundary: missing production observability

In production, client-side errors caught by this boundary are only visible if someone has DevTools open. There's no `fetch` to a logging endpoint, no Sentry-style integration, no `navigator.sendBeacon` fallback. For a community site this may be acceptable at launch, but errors in production are effectively invisible until a user reports them manually.

## Title template produces doubled site names

Every child page sets `title` to a full descriptive string like `"About Kiro - AI-Powered Development Assistant"`. With the new template `%s | Kiro Hub`, the rendered `<title>` becomes `"About Kiro - AI-Powered Development Assistant | Kiro Hub"`. To benefit from the template, child pages need to be migrated to short titles (e.g., `title: "About"`) in a follow-up change.
